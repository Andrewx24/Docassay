# Repository layout

One monorepo holds the spec, both packages and the docs, so a spec change and both implementations land in the same pull request. See [ADR 0001](../adr/0001-monorepo.md).

```text
Docassay/
├── AGENTS.md                  # rules for coding agents (Grok Build, Claude, Copilot)
├── README.md
├── LICENSE                    # Apache-2.0
├── VERSION                    # single shared version for both packages
├── spec/
│   ├── document.schema.json   # parser output, normalized
│   ├── golden.schema.json     # labeled expectations
│   ├── config.schema.json     # docassay.yaml
│   ├── scorecard.schema.json  # output of `docassay run --format json`
│   ├── baseline.schema.json   # .docassay/baseline.json
│   ├── examples/              # one valid example per schema
│   └── fixtures/              # parity corpus: <case>/{document.json, golden.yaml, expected.json}
├── python/
│   ├── pyproject.toml         # Poetry
│   ├── src/docassay/
│   │   ├── __init__.py        # public API: run, verify, load_golden, Document
│   │   ├── models/            # GENERATED from spec/, do not edit
│   │   ├── normalize/         # text.py, numbers.py, dates.py
│   │   ├── golden.py          # load + validate golden files
│   │   ├── config.py          # load + validate docassay.yaml
│   │   ├── scoring/           # tables.py, text.py, order.py, fields.py, chunks.py, aggregate.py
│   │   ├── adapters/          # base.py, registry.py, file.py, docling.py, llamaparse.py, reducto.py
│   │   ├── cache.py
│   │   ├── gate.py            # baseline + check
│   │   ├── verify.py
│   │   ├── report/            # terminal.py, json.py, markdown.py, html.py
│   │   └── cli.py             # Typer app
│   └── tests/
├── js/
│   ├── package.json           # npm package "docassay"
│   ├── src/
│   │   ├── index.ts           # public API: run, verify, loadGolden, Document

│   │   ├── normalize/         # text.ts, numbers.ts, dates.ts
│   │   ├── golden.ts
```

## Mirroring rule

Python and TypeScript use **the same module names and the same function names** (snake_case in Python, camelCase in TypeScript). If `python/src/docassay/scoring/tables.py` has `score_tables`, then `js/src/scoring/tables.ts` has `scoreTables`. A reviewer should be able to open the two files side by side.

## Generated code

`models/` in both packages is generated by `scripts/gen-types.sh` and committed. CI regenerates it and fails if anything differs. Never hand-edit generated files; change the schema instead.
